# Full Stack Emulator — nginx + systemd deployment

How to put the emulator on a Raspberry Pi the same way `NYSERDA-P5-2` and
`SBIR-2991` are deployed: **nginx serves the React SPA and proxies `/api/` to a
FastAPI backend that runs as a systemd service.**

Target layout on the Pi:

```
/home/saxifrage/Desktop/Emulator/   <- git clone
└── full-stack-emulator/
    ├── app.py                  <- uvicorn target (app:app)
    ├── backend/                <- FastAPI, venv, emulator_config.json
    ├── frontend/               <- Vite + React
    └── infra/                  <- everything in this directory
```

| Piece | Where it ends up |
|---|---|
| SPA static files | `/var/www/emulator`, served by nginx on **:80** |
| nginx site | `/etc/nginx/sites-available/emulator` → `sites-enabled/` |
| Backend | `uvicorn app:app` on **127.0.0.1:8000**, unit `emulator-backend` |
| Service env | `infra/emulator.env` (from `emulator.env.example`) |
| Build env | `frontend/.env.production` (from `frontend.env.example`) |

---

## Files in this directory

| File | Purpose |
|---|---|
| `emulator.env.example` | Service tunables — ports, paths, build switches. Copy to `emulator.env`. |
| `frontend.env.example` | Vite build-time vars. Copy to `../frontend/.env.production`. |
| `emulator_config.example.json` | Seed hardware config for a fresh Pi (see [Why the config seed matters](#why-the-config-seed-matters)). |
| `nginx/emulator.conf` | The nginx site: SPA root, `/api/` proxy, health probes. |
| `systemd/emulator-backend.service` | The unit. Paths get rewritten at install time. |
| `install-emulator-service.sh` | One-time (idempotent) installer. Needs root. |
| `run-emulator-backend.sh` | What the unit executes: seed config → build/deploy SPA → `exec uvicorn`. |
| `deploy-frontend.sh` | Ship a UI change without restarting the backend. |
| `.node-path.env` | Generated by the installer. Not committed. |

## Prerequisites

On the Pi, once:

```bash
sudo apt update && sudo apt install -y nginx python3-venv python3-dev git
```

Node.js is needed because the frontend is built **on the Pi**. If you use nvm,
install it as `saxifrage` (not root) — the installer looks for npm under that
user's `~/.config/nvm` and `~/.nvm`, then on `PATH`.

```bash
node --version && npm --version   # run this as saxifrage, must both work
```

## Setup

### 1. Clone and create the virtualenv

Do this as `saxifrage`, **not** with sudo — a root-owned venv is the most common
way this deployment breaks.

```bash
cd ~/Desktop
git clone https://github.com/MicroEraPower/Emulator.git
cd Emulator/full-stack-emulator/backend
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

If the repo is already cloned, just create the venv:

```bash
cd ~/Desktop/Emulator/full-stack-emulator/backend
python3 -m venv venv && venv/bin/pip install -r requirements.txt
```

`requirements.txt` pulls `RPi.GPIO`, `spidev`, `SMrtd`, `SM16uout`,
`SM16univin` and `SM16relind`. Those are Pi-only wheels; on any other host this
step fails, which is why the installer refuses non-ARM machines without
`--force`.

### 2. Run the installer

```bash
cd ~/Desktop/Emulator/full-stack-emulator
sudo ./infra/install-emulator-service.sh
```

It creates `infra/emulator.env` and `frontend/.env.production` from the
examples, finds npm for `saxifrage` and records it in `.node-path.env`, creates
`/var/www/emulator` owned by `saxifrage:www-data`, installs and enables the
nginx site, and installs the systemd unit with the paths rewritten to match this
checkout.

**It also removes `/etc/nginx/sites-enabled/default`.** Debian's stock site is
`listen 80 default_server`, so leaving it in place makes `nginx -t` fail. Only
the symlink is deleted; restore it with
`sudo ln -s /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default`.

### 3. Review the environment file

```bash
nano infra/emulator.env
```

Defaults are correct for a dedicated emulator Pi. The one you may want to change
is `BUILD_FRONTEND` — see [Two update workflows](#two-update-workflows).

If you change `BACKEND_PORT`, change it in `nginx/emulator.conf` too and re-run
the installer; it refuses to install a mismatched pair (exit 23) rather than
leave you with a proxy pointed at nothing.

### 4. Start it

```bash
sudo systemctl enable --now emulator-backend
journalctl -u emulator-backend -f
```

The first start runs `npm ci` and a Vite build, which takes a few minutes on a
Pi. `TimeoutStartSec=600` covers that.

### 5. Verify

```bash
curl -s http://localhost/nginx-health      # -> nginx ok
curl -s http://localhost/backend-health    # -> {"message":"Full Stack Emulator","status":"running",...}
curl -s http://localhost/api/config | head -c 200
systemctl status emulator-backend
```

`/nginx-health` isolates nginx; `/backend-health` proves the proxy chain and
uvicorn. If the first passes and the second 502s, the backend is down — the
journal will say why.

Then browse to `http://<pi-ip>/` — get the address with `hostname -I`.

## Two update workflows

`BUILD_FRONTEND` in `infra/emulator.env` picks which one you get.

**`BUILD_FRONTEND=1` (default, what you asked for — fast lab iteration).**
The service rebuilds and redeploys the SPA on every start, so one command ships
everything:

```bash
cd ~/Desktop/Emulator && git pull
sudo systemctl restart emulator-backend
```

Cost: every restart pays the Vite build, and a UI-only change still bounces the
backend — which discards live emulator state (valve positions, RTD playback
position, the Arctic HP Modbus server).

**`BUILD_FRONTEND=0` — decoupled.**
Restarts are near-instant and the two halves move independently:

```bash
./infra/deploy-frontend.sh              # UI only, backend keeps running
sudo systemctl restart emulator-backend # backend only
```

`deploy-frontend.sh` works in either mode; it is the escape hatch when you want
a UI change live without dropping backend state.

Neither path reloads nginx. nginx reads static files from disk per request, so
replacing them needs no reload — only a changed nginx *config* does, and that is
the installer's job. (This is a deliberate departure from
`P5-2/infra/dev-env/run-p5-2-backend.sh`, which reloads nginx and `sudo`s its
file copies on every start. That requires passwordless sudo for the service
user; here `/var/www/emulator` is owned by the service user instead, so the hot
path needs no privilege at all and cannot hang on a sudo password prompt.)

## Why the config seed matters

`backend/emulator_config.json` is **git-ignored**, and correctly so — the UI
rewrites it through `PUT /api/config`, so a tracked copy would produce a dirty
working tree after every session.

The consequence is that a fresh clone has no config file, and
`ConfigStore.load()` in [`backend/src/config/store.py`](../backend/src/config/store.py)
responds by calling `build_default_config()` and writing generic defaults.
Silently. You would get a running emulator with the wrong board count, wrong
valve channels, and no Arctic HP ESP32 addresses.

`infra/emulator_config.example.json` is a tracked snapshot of a real working
config (6 RTD boards, CV1–CV3, OV1–OV8, two Arctic heat pumps). With
`SEED_CONFIG=1`, `run-emulator-backend.sh` copies it into place **only if no
config exists**, and never overwrites one. To refresh the snapshot after
retuning the rig through the UI:

```bash
cp backend/emulator_config.json infra/emulator_config.example.json
git add infra/emulator_config.example.json && git commit -m "infra: refresh emulator config snapshot"
```

## Operating the service

```bash
sudo systemctl start|stop|restart emulator-backend
systemctl status emulator-backend
journalctl -u emulator-backend -f            # follow
journalctl -u emulator-backend -n 200        # last 200 lines
journalctl -u emulator-backend --since "10 min ago"
journalctl -u emulator-backend -p err        # errors only
sudo tail -f /var/log/nginx/emulator.error.log
```

Startup and failures are prefixed `[emulator]`, `[emulator][WARN]`, or
`[emulator][FAIL:<code>]`, so `journalctl -u emulator-backend | grep FAIL` gets
you straight to the cause.

## Troubleshooting

Read the exit code first: `systemctl status emulator-backend` shows it as
`status=NN`.

| Exit | Meaning | Fix |
|---|---|---|
| `10` | Project layout wrong | The checkout moved or is incomplete. Re-run `sudo ./infra/install-emulator-service.sh` to rewrite the unit's paths. |
| `11` | No virtualenv | `cd backend && python3 -m venv venv && venv/bin/pip install -r requirements.txt` — as `saxifrage`, not root. |
| `12` | venv has no uvicorn | `backend/venv/bin/python3 -m pip install -r backend/requirements.txt` |
| `13` | npm not found | Re-run the installer to regenerate `.node-path.env`, or set `NPM=` in `emulator.env`, or set `BUILD_FRONTEND=0`. |
| `14` | Frontend build failed | Read the npm output in the journal. Usually a bad `package-lock.json` or an out-of-memory Vite build — try `npm ci` by hand as `saxifrage`. |
| `15` | Frontend deploy failed | `sudo chown -R saxifrage:www-data /var/www/emulator` |
| `16` | Config seeding failed | `backend/` is not writable by the service user: `sudo chown -R saxifrage:saxifrage backend` |
| `203` | `ExecStart` not executable | `chmod +x infra/*.sh` |
| `23` | (installer) env/nginx mismatch | `BACKEND_PORT` or `FRONTEND_DEST` in `emulator.env` disagrees with `nginx/emulator.conf`. The error prints the `sed` to fix it. |

Symptom-first:

| Symptom | Cause | Fix |
|---|---|---|
| **502 Bad Gateway on `/api/...`** | Backend down or on a different port | `systemctl status emulator-backend`; check `BACKEND_PORT` matches `proxy_pass` in the nginx conf |
| **Rolling 502s, backend restarts constantly** | uvicorn `--reload` | Never add `--reload` under systemd. The app writes `emulator_config.json` and `emulator_runtime.json` while running, which trips the file watcher. The runner deliberately omits it. |
| **Blank page, 404s for `/assets/*.js`** | Stale cached `index.html` after a redeploy | The conf sets `no-store` on `index.html`; hard-refresh once. If it persists, the deploy left a partial `dist/` — re-run `./infra/deploy-frontend.sh`. |
| **403 Forbidden on `/`** | nginx cannot read `/var/www/emulator` | `sudo chown -R saxifrage:www-data /var/www/emulator && sudo chmod -R a+rX /var/www/emulator` |
| **Deep link / refresh gives 404** | SPA fallback missing | Confirm `try_files $uri $uri/ /index.html;` is in the installed site: `sudo nginx -T \| grep -A3 'location /'` |
| **Config reset to defaults** | No config file at start | See [Why the config seed matters](#why-the-config-seed-matters). Set `SEED_CONFIG=1`. |
| **Arctic HP / valves / RTD do nothing** | Hardware not reachable by the service user | `saxifrage` needs the `dialout`, `i2c`, `gpio`, `spi` groups: `sudo usermod -aG dialout,i2c,gpio,spi saxifrage`, then reboot. Check `/dev/ttyACM0` exists and matches `arctic_hp.port.serial_file` in the config. |
| **`nginx -t` fails: duplicate default_server** | Stock default site re-enabled | `sudo rm /etc/nginx/sites-enabled/default && sudo systemctl reload nginx` |
| **Service gives up after repeated failures** | `StartLimitBurst=5` reached | Fix the underlying exit code, then `sudo systemctl reset-failed emulator-backend && sudo systemctl start emulator-backend` |

Reading the whole effective nginx config, including which site won:

```bash
sudo nginx -T | less
```

## Uninstall

```bash
sudo systemctl disable --now emulator-backend
sudo rm /etc/systemd/system/emulator-backend.service
sudo systemctl daemon-reload
sudo rm /etc/nginx/sites-enabled/emulator /etc/nginx/sites-available/emulator
sudo ln -sfn /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo rm -rf /var/www/emulator
```

## Differences from P5-2 and SBIR

Deliberate, and why:

| | P5-2 / SBIR | Here |
|---|---|---|
| Static deploy privilege | `sudo cp` + `sudo chown` in the runner on every start | Serving dir owned by the service user; **no sudo in the hot path** |
| nginx reload | `sudo systemctl reload nginx` every start | Only at install time — static file swaps don't need it |
| nginx config install | Copied over `sites-available/default` on every start | Installed once to `sites-available/emulator`, validated with `nginx -t` before reload |
| Env config | `Environment=` lines inside the unit (P5-2); `EnvironmentFile=/etc/smith/...` (SBIR) | `EnvironmentFile=` pointing at `infra/emulator.env`, in-repo and documented |
| Paths in the unit | Hard-coded, break silently if the checkout moves | Rewritten at install time from the actual checkout location |
| Health check | SBIR expects `/health` | Backend has none; nginx exposes `/nginx-health` and proxies `/backend-health` to the backend's `/` route |
