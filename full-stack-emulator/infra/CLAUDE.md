# CLAUDE.md — `full-stack-emulator/infra/`

Deployment layer for the Full Stack Emulator: nginx serves the built React SPA
and reverse-proxies `/api/` to a FastAPI backend running under systemd.
Nothing in this directory is imported by the application; it is shell, nginx
config, and one systemd unit.

Operator instructions: [README.md](README.md). Rationale: [DESIGN.md](DESIGN.md).

## Deployed shape

| | Value |
|---|---|
| Host | Raspberry Pi, user `saxifrage` |
| Checkout | `/home/saxifrage/Desktop/Emulator/full-stack-emulator` |
| nginx | port 80, site `emulator`, root `/var/www/emulator` |
| Backend | `uvicorn app:app` on `127.0.0.1:8000` |
| Unit | `emulator-backend.service`, journal identity `emulator-backend` |

## Execution order

```
install-emulator-service.sh        (once, root)
  ├─ emulator.env            ← emulator.env.example      (if absent)
  ├─ ../frontend/.env.production ← frontend.env.example  (if absent)
  ├─ .node-path.env          ← npm discovered for the service user
  ├─ mkdir + chown FRONTEND_DEST to SERVICE_USER:www-data
  ├─ validate nginx conf against emulator.env, install site, disable default, nginx -t, reload
  └─ install unit with paths/User rewritten to this checkout, daemon-reload

systemctl start emulator-backend   (every start)
  └─ run-emulator-backend.sh
       ├─ [0] layout preflight
       ├─ [1] seed backend/emulator_config.json if absent   (SEED_CONFIG)
       ├─ [2] npm ci (if stale) → vite build → copy dist → /var/www/emulator  (BUILD_FRONTEND)
       └─ [3] exec uvicorn app:app --host --port --log-level
```

`deploy-frontend.sh` is step [2] standalone, for shipping UI changes without
restarting the backend.

## Files

| File | Committed | Notes |
|---|---|---|
| `emulator.env.example` | yes | Template. Every key documented inline. |
| `emulator.env` | **no** | Live config, created by the installer, mode 600. |
| `frontend.env.example` | yes | Template for `../frontend/.env.production`. |
| `emulator_config.example.json` | yes | Hardware config snapshot used to seed a fresh Pi. |
| `.node-path.env` | **no** | Machine-specific npm/PATH, generated by the installer. |
| `nginx/emulator.conf` | yes | Literal values must match `emulator.env`; the installer enforces this. |
| `systemd/emulator-backend.service` | yes | Absolute paths are rewritten at install time. |
| `install-emulator-service.sh` | yes | Root. Idempotent. All privileged work lives here. |
| `run-emulator-backend.sh` | yes | Runs as the service user. **No sudo.** |
| `deploy-frontend.sh` | yes | Runs as the service user. **No sudo.** |

## Environment variables

Consumed by the shell scripts, **not** by the FastAPI application — the backend
reads no environment variables at all. Adding a key here does nothing unless a
script uses it.

| Key | Default | Effect |
|---|---|---|
| `BACKEND_HOST` | `0.0.0.0` | uvicorn `--host` |
| `BACKEND_PORT` | `8000` | uvicorn `--port`; must match `proxy_pass` in the nginx conf |
| `BACKEND_LOG_LEVEL` | `info` | uvicorn `--log-level` |
| `APP_ENV` | `lab` | Exported and echoed in the banner; no behavioural effect |
| `FRONTEND_DEST` | `/var/www/emulator` | Deploy target; must match nginx `root` |
| `BUILD_FRONTEND` | `1` | `1` = service rebuilds the SPA each start; `0` = uvicorn only |
| `INSTALL_FRONTEND_DEPS` | `1` | `1` = `npm ci` when `node_modules` is stale |
| `SEED_CONFIG` | `1` | `1` = copy the example config when none exists |
| `NPM` | unset | Explicit npm path; overrides discovery |

**Append, never renumber.**

| Code | Meaning | Raised by |
|---|---|---|
| 2 | Bad usage | all |
| 3 | Not root | installer |
| 4 | Not an ARM host | installer |
| 10 | Project layout wrong | runner, deploy, installer |
| 11 | Virtualenv missing | runner |
| 12 | uvicorn missing | runner |
| 13 | npm not found | runner, deploy |
| 14 | Frontend build failed | runner, deploy |
| 15 | Frontend deploy failed | runner, deploy |
| 16 | Config seeding failed | runner |
| 20 | nginx not installed | installer |
| 21 | `nginx -t` failed | installer |

## Logging

Scripts emit `[emulator] …`, `[emulator][WARN] …`, `[emulator][FAIL:<code>] …`
(the deploy script uses `[deploy-frontend]`). No timestamps — journald adds its
own. The runner installs an `ERR` trap so a `set -e` abort reports the failing
line and command instead of exiting anonymously.

```bash
journalctl -u emulator-backend -f
journalctl -u emulator-backend | grep FAIL
```

Backend application logs come from `backend/src/utils/logging.py`
(`logging.basicConfig`, INFO) and land in the same journal.

## Invariants — do not break these

1. **No `--reload` in the service path.** The app writes JSON state files while
   running; the watcher would restart it in a loop and nginx would serve rolling
   502s.
2. **No `sudo` in `run-emulator-backend.sh` or `deploy-frontend.sh`.** A sudo
   password prompt inside a systemd unit hangs until `TimeoutStartSec`.
3. **`BACKEND_PORT` and `FRONTEND_DEST` must agree with `nginx/emulator.conf`.**
   nginx cannot read env vars; the installer greps the conf and fails on
   mismatch.
4. **Never overwrite an existing `backend/emulator_config.json`.** It is live
   hardware configuration edited through the UI.
5. **Do not add `ProtectSystem` / `PrivateDevices` / `DynamicUser` to the unit**
   without re-testing serial, I2C, SPI and GPIO. The emulator drives real
   devices.
6. **`exec` the final uvicorn** so systemd tracks the real PID and signals reach
   the app.

## Changing things

| Change | Do this |
|---|---|
| Backend port | Edit `emulator.env` **and** `nginx/emulator.conf`, then re-run the installer |
| nginx behaviour | Edit `nginx/emulator.conf`, re-run the installer (it runs `nginx -t` before reloading) |
| Unit restart policy / env files | Edit `systemd/emulator-backend.service`, re-run the installer |
| Node version | Re-run the installer to regenerate `.node-path.env` |
| Checkout moved | Re-run the installer; it rewrites the unit's absolute paths |
| Refresh the config snapshot | `cp backend/emulator_config.json infra/emulator_config.example.json` and commit |
